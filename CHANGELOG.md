## [1.0.2] — 2026-10-26

### Added

- `album/rng.c`: one seedable generator for every game. `ALBUM_SEED` fixes the
  layout (`album_rand_below` / `album_rng_seed`), so a failing smoke-test run can
  be reproduced locally; without it the seed still comes from `time(NULL)`.
- CI: a second full-app smoke run whose seed changes on every push, alongside the
  pinned one. The pinned run stays reproducible; the extra run keeps exercising
  fresh minesweeper/snake/2048 layouts.

### Fixed

- Minesweeper flood-fill (`album/ms.c`) could push the same cell onto its 81-slot
  stack once per zero neighbour that reached it, overflowing the array on about
  2% of boards. Linux CI hit it as `*** stack smashing detected ***` during the
  scripted smoke test; MinGW builds silently corrupted adjacent memory instead.
  Cells are now queued at most once, so the deepest stack is bounded by the
  board size (measured worst case: 38 of 81 slots).
- The smoke test is reproducible: CI pins `ALBUM_SEED=20261025`, and two runs
  with the same seed produce identical state-machine output.

## [1.0.1] — 2026-10-25

- CI: build the PC test harness and run the full-app smoke test on every push.
- CI: install `fonts-noto-cjk` before regenerating assets, so the art pipeline also runs
  on a clean Linux runner.

### Fixed

- Unit test asserted `N_ABS >= 2` for the absolute-axis bitmask, which is only true
  where `unsigned long` is 32 bits. The assertion now checks the actual capacity
  (`N_ABS * 8 * sizeof(unsigned long) >= ABS_MAX + 1`), so the suite passes on
  64-bit Linux as well as on MinGW.
- The asset generators no longer hardcode `C:\Windows\Fonts\...`: `tools/fontkit.py`
  resolves a CJK font per platform (Microsoft YaHei / SimHei on Windows, Noto Sans CJK
  on Linux, DejaVu as a last resort) and honours the `ALBUM_FONT` environment variable.
  When no candidate is installed, rendering falls back to Pillow's default bitmap font.

## [1.0.0] — 2026-10-25

First public release. Source-only repository: every bitmap, button sprite, chess
piece, tetromino, snake segment and landscape photo is generated by the Python
scripts in `tools/`, so the checkout stays small and nothing binary is licensed.

### Added

- DRM-direct renderer for a 1024×600 panel (double buffer + page flip, no X11,
  Wayland, Qt, SDL, libpng or libjpeg).
- Password-locked photo album: manual slideshow, auto slideshow with configurable
  interval, and a 3×3 thumbnail browser.
- Options screen: auto-play interval, slideshow transition, back to album, exit.
- Six mini games: 2048, Tetris, Snake, Tic-Tac-Toe, Minesweeper, Xiangqi (象棋).
- `touch.c`: poll-based touch reader with press/release separation and a timeout,
  so auto-play keeps running while idle and buttons show a pressed state.
- PC test harness (`test/`): DRM replaced by a plain memory surface, touch panel
  replaced by a scripted click list; `make -C test unit` runs the logic unit tests,
  `make -C test run` drives the real state machine through 46 scripted touches.
- Art pipeline (`tools/`): every asset is reproducible from source; `make assets`
  regenerates the whole `bmp/` tree (requires Python 3 + Pillow).
- `build.sh` for the aarch64 cross build, plus a `.gitignore` that keeps generated
  bitmaps, objects and binaries out of the tree.

### Platform facts (measured on the board, not assumed)

- 1024×600 panel, DRM/KMS framebuffer, 32 bpp XRGB8888.
- Resistive/capacitive touch panel exposed through `evdev`; press/release events
  arrive as separate `SYN`-terminated packets, and the driver is identified at
  runtime rather than hard-coded.
- Vendor `libDRMwrap.so` is required at runtime for the panel initialisation path;
  it is **not** vendored here (see README → Building for the board).

### Known limitations

- Audio/video playback is not implemented.
- Single buffered slide transitions can tear on very fast panel refreshes.
- Only uncompressed BMP images are accepted by the album loader.
- The default password is trivial (`FNV-1a` of a short string) — it is a UI gate,
  not a security boundary.
